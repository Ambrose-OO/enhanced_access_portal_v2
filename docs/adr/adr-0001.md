
# ADR-0001: Architecture decision records (ADR)

Date: 2026-08-04

Status: Accepted

## Context
There will exist significant technical decisions on this project,
surrounding platforms, frameworks, pipelines and hosting choices.
Therefore, there sits a need for technical decision rationale to be
preserved for assessment evidence and future maintenance. 
Without a record, past decisions can only be blindly accepted or blindly 
changed. Which affects the planned Kaizen (Learn) stage of the DevOps
pipeline integrated into the iterative software development workflow.

## Decision
As a result, architecturally significant decisions will be recorded 
as architecture decision records (Nygard, 2011), stored in 
docs/adr/ as sequentially numbered Markdown files, using Nygard's 
format with an added "Options considered" section.

## Consequences
Positive: 

- There will be a decision log the DevOps report and viva can 
reference.

- Rejected alternative decisions can still be documented, not lost. 
For future learning and reflection purposes.

Negative: 

- There sits a small documentation overhead per decision

- The log only has value if maintained, so ADR review is included in the 
Learn (Kaizen) stage of each iteration.

## References
Nygard, M. (2011) 'Documenting architecture decisions', Cognitect, 15 November. Available at: https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions (Accessed: 4 August 2026).
