
# ADR-0002: Use GitHub Actions for CI/CD over GitLab CI/CD

Date: 2026-08-04

Status: Accepted

## Context
The assignment brief names GitLab as an example CI/CD tool, however,
the inherited IEAP codebase, its issue tracking and its Kanban board
are already live on GitHub, and the pipeline must run builds, tests and
security scans on every commit, then deploy to Render, on free-tier
allowances and with a single developer maintaining it.

## Options considered
1. GitLab with GitLab CI/CD — The brief's named example; free tier
   includes CI/CD minutes; this would require migrating or mirroring the
   repository from GitHub, adding setup and ongoing sync overhead.
2. GitHub with GitHub Actions — GitHub's built-in automation tool,
   which runs workflows (jobs defined in YAML under .github/workflows)
   in response to repository events such as pushes and pull requests
   (GitHub, no date); no migration needed.
3. Keep the repository on GitHub and mirror it to GitLab for CI only —
   possible, but couples two platforms and doubles the surface to
   maintain for no functional gain.

## Decision
GitHub Actions has been chosen, enabling one to keep source control, the 
Kanban backlog and the pipeline on one platform.

## Consequences
Positive: 
- No repository migration
- Pull-request checks and branch protection integrate natively
- Github repo pushes can trigger Render auto-deploys, all under one pipelines; 
enables github repo and render to connect under one pipeline
- One platform to evidence in the DevOps report, instead of many, given time constraints

Negative: 
- The choice diverges from the brief's named example — mitigated because the
brief lists GitLab as an example only, and Task 3 asks for elements "used or could 
have used" so GitLab is documented there as the considered alternative. 
- The  project is also coupled to a single vendor for Software Configuration Management (SCM)
and CI.
